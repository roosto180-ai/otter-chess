تم إعداد هذه النسخة من المصدر الرسمي https://github.com/PeargentLabs/otter-chess عند الالتزام `3e1e6c92f04010d3352be1625fe780f6f826aa06`، بتاريخ 21 أكتوبر 2026. لم تُنشر من هذه الجلسة: أداة GitHub المتصلة لا تتيح إنشاء fork أو تفعيل Pages، والمتصفح وصل إلى شاشة تسجيل الدخول. لا يوجد رابط عام لنسخة معدلة مُختبَرة حتى الآن.

## التشغيل على Windows

ثبّت Node.js 22.18 أو أحدث (يوصى بإصدار LTS 24). من مجلد النسخة:

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-Otter.ps1
```

أو يدويًا:

```powershell
cd docs
npm ci
npm test
npm run build
npm run serve
```

افتح http://127.0.0.1:3000/play/ . يحتاج التثبيت الأول إلى الإنترنت لتنزيل حزم البناء والخطوط. الأوزان ومحرك ONNX وStockfish موجودة محليًا، ويتحقق البناء من بصماتها. من «Set Up Engines» اضغط زري Download ثم Ready. التنزيل هنا من موقعك نفسه، ويُخزّن في المتصفح. لا تستخدم `next start`؛ هذا مشروع تصدير ثابت. لإيقاف الخادم اضغط Ctrl+C.

## الاستخدام

- اختر زمنًا جاهزًا أو أدخل دقائق مخصصة وزيادة بالثواني ثم اضغط «تطبيق الوقت المخصص». الاختيار المعروض هو الذي يبدأ به اللقاء.
- تستطيع ضبط وقتك، أو وقت Otter، أثناء اللعب وبعد الصفر. زر «وقتي 5 دقائق» يضبط وقتك إلى 300 ثانية.
- بعد انتهاء اللقاء تُحفظ النتيجة وPGN في سجل المباريات المحلي وتبقى اللوحة في موضعها الأخير. تعديل الساعة وحده لا يبدّل النتيجة؛ اضغط «متابعة من نفس الموضع — وضع تحليلي».
- في المتابعة يبقى نموذج Otter وتصنيفه ونافذة تاريخ النقلات كما هي. الساعات ثابتة وقابلة للتعديل، ولا تنشأ نتيجة أو نقاط تصنيف ثانية.
- عند كش مات أو بات لا توجد نقلة قانونية. زر المتابعة يُعلن التراجع إلى قرارك السابق ويفتح فرعًا بديلًا: يتراجع نقلة أو نقلتين حتى يصبح الدور لك، مع إبقاء PGN النهائي الأصلي في سجل المباريات. لا يُنشئ نقلات غير قانونية بعد المات.
- بعد تعادل بالتكرار أو بقاعدة الخمسين نقلة يمكن المتابعة من الموضع نفسه إذا بقيت نقلات قانونية. يبقى سجل النقلات وعداد نصف النقلة وحقوق التبييت والأخذ بالتجاوز محفوظًا.
- استخدم «عرض / نسخ PGN» لحفظ الفرع الحالي. «مباراة جديدة / القائمة» ينهي الفرع الحالي ويعود للقائمة.

## الحفاظ على Otter

الأوزان هي `model_fp16.onnx` نفسها التي ينزّلها الموقع الرسمي، بحجم 30,880,660 بايت، وليست ملف FP32 القديم `policy_model.onnx` الموجود في المستودع. إصدار Hugging Face المثبّت: `eb8dc98b551d2b0744ba45e98fac23cf1af8c629`.

SHA-256:
`d9067fafb23f13f12eb92683ca412eda6e6b8ea3b09f3fb9b504404871014536`

يحتوي `docs/assets-manifest.json` على مصادر وبصمات جميع أصول التشغيل. يتحقق المتصفح أيضًا من بصمة النموذج قبل تخزينه. دليل `INFERENCE-PARITY.json` يثبت التطابق النصي لدوال `runModelInference` و`runModelInferenceAtElo` و`resolveEloAndClock` مع المصدر الرسمي. ظلت تجهيزات اللوحة والقواميس ونافذة آخر 20 نقلة والتصنيف واختيار أعلى احتمال وإعداد تحسين ONNX `basic` كما هي. نسخة onnxruntime-web هي 1.27.0.

الساعة تدخل ضمن تكييف النموذج أصلًا؛ لذلك تغيير زمن Otter أو نوع الوقت قد يغيّر نقلته كما يفعل على الموقع الرسمي. الأوقات المخصصة تُحوَّل إلى مجموعات الزمن الثلاث الأصلية، وليست فئات جديدة دُرِّب عليها النموذج. لا نعِد بتطابق رقمي بتًا ببت بين معالجات ومتصفحات مختلفة، ولا بتصنيف Elo فعلي مُعاير لكل إعداد جديد.

## النشر الدقيق على GitHub Pages

1. سجّل الدخول إلى GitHub وافتح https://github.com/PeargentLabs/otter-chess/fork وأنشئ fork عامًا باسم `otter-chess`، مع إبقاء `main`.
2. نزّل fork محليًا. انسخ محتويات هذه الحزمة فوقه **دون نسخ مجلد `.git`** ودون `node_modules` أو `.next` أو `out`. احذف `docs/public/policy_model.onnx` القديم إذا بقي؛ النموذج الصحيح الجديد هو `model_fp16.onnx`.
3. افتح Settings → Pages واختر Source: GitHub Actions.
4. ادفع الملفات إلى `main` بالأوامر التالية داخل fork الذي نسخته، مع كتابة اسمك بدل YOUR_LOGIN:

```powershell
git remote -v
git add -A
git commit -m "Add editable clocks and faithful Otter continuation mode"
git push origin main
```

5. من Actions شغّل «Deploy docs site» إن لم يبدأ تلقائيًا. إذا كانت إجراءات fork معطّلة، فعّلها من Actions أولًا. يشغّل المسار الاختبارات، ويتحقق من الأصول، ويبني الموقع، وينشره.
6. بعد نجاح مهمة deploy افتح `https://YOUR_LOGIN.github.io/otter-chess/play/`. هذا نمط رابط متوقّع، **وليس رابط نشر تم التحقق منه هنا**. اسم مستودع مختلف يعمل أيضًا لأن المسار يُؤخذ من `configure-pages` تلقائيًا.
7. تحقّق من تنزيل المحرك، واللعب ورد Otter، وضبط الوقت للصفر ثم 5 دقائق والمتابعة. إذا استخدمت نطاقًا مخصصًا أعد النشر لتحديث المسارات.

الموقع ثابت: لا يحتاج خادم Python أو GPU بعيدًا، ولا توجد عملية ذكاء اصطناعي تنام عند عدم الزيارة. ينفّذ جهاز الزائر الاستدلال. يمكن استضافته كذلك على أي خادم ملفات ثابتة، باستخدام محتويات `docs/out` المبنية للمسار والنطاق المطلوبين. تجنّب رفع بناء `/otter-chess` إلى جذر نطاق مختلف دون إعادة البناء.

## القيود

- الاستدلال يستهلك ذاكرة ومعالج جهازك؛ سرعة الرد تعتمد على المتصفح والجهاز. اختُبر WASM فعليًا؛ لم يُختبر جهاز GPU منفصل. لا حاجة لخادم نموذج مستمر.
- GitHub Pages لا يضمن توافرًا مطلقًا، وله حدود خدمة وحجم ونقل بيانات. حجم هذه النسخة أقل من حد الموقع البالغ 1GB؛ راجع https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits .
- المتابعة تحليل غير مصنّف، وتتوقف الساعات فيها عمدًا حتى عند الصفر. تغيير الوقت لا يُبطل النتيجة الأصلية المسجلة.
- سجل المباريات المنتهية والتصنيف مخزّنان في هذا المتصفح فقط. تحديث الصفحة يفقد الفرع أو اللقاء الجاري غير المصدَّر؛ صدّر PGN قبل إغلاقها. لا توجد مزامنة حسابات أو تخزين سحابي أو لعب متعدد الأشخاص.
- تشغيل الملفات مباشرة عبر `file://` غير مدعوم. استخدم localhost أو HTTPS، لأن Workers وCache وWebGPU تحتاج سياقًا مناسبًا.
- اختبارات المتابعة القانونية لا تعني السماح بحركة بعد مات في الموضع نفسه؛ ذلك مستحيل بقواعد الشطرنج، لذلك يُستخدم فرع سابق معلن.

### أوامر تجهيز fork بعد إنشائه

فك ضغط `otter-chess-source.zip` أولًا. من المجلد الذي يحتوي `otter-chess` المستخرج، نفّذ مع استبدال YOUR_LOGIN باسم حسابك:

```powershell
git clone https://github.com/YOUR_LOGIN/otter-chess.git otter-chess-fork
robocopy .\otter-chess .\otter-chess-fork /E /XD .git node_modules .next out /XF *.tsbuildinfo next-env.d.ts
cd otter-chess-fork
if (Test-Path -LiteralPath docs/public/policy_model.onnx) { Remove-Item -LiteralPath docs/public/policy_model.onnx }
git add -A
git commit -m "Add editable clocks and Otter continuation analysis"
git push origin main
```

نتيجة robocopy بين 0 و7 تعني نجاحًا عاديًا. هذه الأوامر لا تفعّل Pages تلقائيًا؛ اختر GitHub Actions في Settings → Pages كما ورد أعلاه. لا ترفع `otter-chess-pages.zip` إلى المستودع بدل ملفات المصدر؛ الحزمة الثانية هي ملفات موقع مبنية للمعاينة تحت `/otter-chess`، بينما يعيد مسار Actions البناء للنطاق الحقيقي.
